## 1. 目的

プレイヤーが**化学の知識ゼロで始められ、ゲームを進めるにつれて「作ったもの・聞いた話」として化学の知識が自然に身についていく**ことを、本作の中核体験として設計する。

主人公は知識を持つ化学者だが、プレイヤーは知識を持たない。この乖離を「レシピ通りに調合する所作の中で、なぜその手順なのかを1行添えることで、プレイヤーが後から『そうだったのか』と納得できる」構造に変換するのが本設計の狙いである。

**変更の核心（2026-11-26 承認済み）**:
- 調合は「予測→実験→パラメータ調整」の学習ループではなく、**レシピカードに従って手順を順に実行するだけ**の所作になる
- 予測フェーズ・パラメータ段階解放・learning.ts は削除する
- 知識ノートは「獲得管理するパラメータ」ではなく、**自動で貯まるメモ帳＋ロードマップ表示**になる
- 進み方は Dr.STONE 式：**依頼を解くたびに次の段階の道具・知識・素材が開け、解ける問題の範囲が一段広がる**

## 2. 設計原則（改訂版）

| # | 原則 | 内容 |
|---|------|------|
| P1 | 新概念は1エピソードに1つ | 認知負荷を抑える。新しい概念は、その回の依頼を解くのに必要なものだけをレシピの「なぜこの手順か」で導入する |
| P2 | 見せてから名付ける | まず現象を調合所作で体験させ、その後にレシピの解説行（作中表現→化学名）で言葉を与える。専門用語の先行開示をしない |
| P3 | 手順ミスは教材 | 作り間違えてもゲームオーバーにせず、品質段階の変化と依頼人の反応の小分岐にだけ効かせる。「なぜそうなったか」はレシピの注意書きで補う |
| P4 | ヒントはレシピとノートだけ | ラボで参照できる情報は、レシピカードの記載内容と、知識ノートに自動記録済みの内容に限る。未記録の答えをヒントで先出ししない |
| P5 | 間隔反復 | 過去エピソードの概念は、後のエピソードのレシピで文脈を変えて再利用する（例: Ep.1 の酸の使い分けを Ep.2 の染料調合で使う） |
| P6 | 所作の中に学びがある | 化学者は答えを語る役ではなく、レシピの「なぜ」を1行で添える役。分析と判断の主体はプレイヤーから**レシピの手順実行**へ移す |

## 4. 遊び方の基本ループ（改訂版）

各依頼の基本フローを次の5ステップに統一する。

```
会話（観察・聞き取り） → レシピ提示 → 手順実行 → 納品・反応 → ノート自動記録＋ロードマップ更新
```

| ステップ | プレイヤーの行為 | 対応フェーズ | 実装先（現行構成） |
|----------|------------------|--------------|--------------------|
| 会話 | 依頼人と話し、依頼品・背景を調べ、着目点（分析タグ）を集める | フェーズ1: 対話 | DialogueScene / dialogueEngine |
| レシピ提示 | レシピカードを見る（材料・手順・「なぜこの手順か」1行） | フェーズ2 冒頭 | LabScene / recipeEngine |
| 手順実行 | 手順を順番に実行する（「次にやる手順」を選ぶだけ、数値選択なし） | フェーズ2: ラボ | LabScene / recipeEngine / treatmentEngine |
| 納品・反応 | 完成品を渡し、依頼人の反応・会話の続きを見る | フェーズ3: 結果 | ResultScene / DialogueScene / fateEngine |
| ノート自動記録 | 作ったもの・聞いた話が知識ノートに自動追記され、ロードマップが1段進む | フェーズ3 末尾 | knowledge.ts / GameState / HUDScene |

## 5. システム設計（改訂版）

### 5.1 知識ノート（Field Notes）— 自動メモ帳＋ロードマップ

プレイヤーが**作ったもの・聞いた話**として化学概念が自動で蓄積される。主人公の手帳という体裁で、ゲーム内いつでも参照できる。ロードマップ表示（現在の段階と、次に届く段階の予告）を同一画面内の一区画（タブ相当）として兼ねる。

**データモデル（改訂版）**

```ts
type KnowledgeNote = {
  id: string              // 例: 'rust', 'black-rust', 'acid-phosphoric'
  worldTerm: string       // 作中表現（最初に表示）: '錆'
  plainText: string       // 平易な説明: '金属が空気と水に食われた跡'
  chemTerm?: string       // 化学名（レシピ解説で併記される）: '酸化鉄'
  chemText?: string       // 化学的な補足: '鉄が酸素と結びついたもの'
  source: 'recipe' | 'dialogue' | 'observation'  // 記録された経路
  learnedAt: string       // 記録エピソード: 'ep01'
  relatedNotes: string[]  // 関連ノートID
  roadmapStage: number    // どのロードマップ段階で開放されるか
}
```

**運用ルール（改訂版）**

- 記録前: その概念は会話・レシピで作中表現のみで言及される
- 記録の瞬間: レシピ実行完了時、または会話・観察の節目で**自動的に**追記される（プレイヤー操作不要）
  - 例: リン酸で錆を落とすレシピを実行完了 → 「リン酸 — 錆を溶かすが金属を傷めにくい酸。化学では H₃PO₄ と書く」が自動記録
- 記録後: 以降のレシピカード・会話で化学名が併記されるようになる
- ラボの参照情報は、レシピカードの記載内容と、記録済みノートの内容だけから構成する（原則 P4）
- **ロードマップ区画**: 現在の段階（例: 第1段「酸と錆の基礎」）と、次の段階の予告（例: 第2段「染料と液の相性」で開く道具・素材）を表示する

**EP01 で記録されるノート（案・自動記録順）**

| id | 作中表現 | 平易な説明 | 化学名 | 記録トリガー | roadmapStage |
|----|----------|------------|--------|--------------|--------------|
| rust | 錆 | 金属が空気と水に食われた跡 | 酸化（腐食） | 会話で剣を見た時 | 1 |
| black-rust | 黒錆 | 表面を覆う黒い錆の層 | Fe₃O₄ | レシピ「黒錆の除去」実行時 | 1 |
| chloride-rust | 白っぽい錆 | 海の塩が運んだ、白灰色の錆 | 塩化物錆（FeCl₂ 系） | 会話で出自（港町）を聞いた時 | 1 |
| acid-phosphoric | 穏やかな酸 | 錆を溶かすが金属を傷めにくい酸 | リン酸（H₃PO₄） | レシピ「リン酸による除去」実行時 | 1 |
| acid-hydrochloric | 荒い酸 | よく溶かすが金属まで攻撃し、熱で有毒ガスも出す | 塩酸（HCl） | レシピ注意書き・反応差分で言及時 | 1 |
| concentration-care | 濃さの加減 | 濃いほど強力だが、相手まで傷める | 濃度の概念 | レシピの手順「薄めて使う」実行時 | 1 |
| heat-care | 熱の加減 | 熱は反応を速めるが、暴走と副産物も招く | 温度依存性・副反応 | レシピの手順「温めすぎない」実行時 | 1 |

### 5.2 レシピエンジン（recipeEngine）— 「レシピ提示＋手順実行」モデル

旧 `treatmentEngine.ts` のパラメータ選択（酸種・濃度・温度・手順・反応・濾過）を廃止し、**レシピカードに従った手順実行**に変更する。

**レシピデータ構造（案）**

```ts
type Recipe = {
  id: string                    // 'ep01-rust-removal'
  title: string                 // '黒錆の除去'
  client: string                // 'ガルド'
  materials: Material[]         // 材料リスト（表示用）
  steps: RecipeStep[]           // 実行手順（順序固定）
  whyOneLiner: string           // 「なぜこの手順か」1行
  qualityTiers: QualityTier[]   // 品質段階の定義（手順正確さで決まる）
  cautionNotes?: string[]       // 注意書き（ミス時の反応差分用）
}

type RecipeStep = {
  id: string
  instruction: string           // 表示テキスト: 'リン酸を規定量、蒸留水で3倍に薄める'
  actionType: 'measure' | 'mix' | 'heat' | 'filter' | 'wait' | 'observe'
  why: string                   // この手順の理由1行: '濃いままでは金属まで溶かすため'
  expectedObservation?: string  // 期待される観察: '液が淡い緑色に変わる'
}
```

**判定ルール（簡略化）**

- 手順を順に正しく選べば **成功**（品質: 良好〜完全）
- 手順を間違える・飛ばす・順序違い → **品質が1段階下がる**（完全→良好→不完全）、依頼人の反応に小分岐
- ゲームオーバー・事故結末（金属侵食・ガス事故）は結末分岐から外し、「注意書きを無視したときの反応差分」としてのみ残す（判断ポイント1）
- 数値パラメータ（濃度 Lv.3〜4、温度 35〜45℃ 等）は UI 選択から外し、**レシピの記載内容**として手順テキストに埋め込む

---

### 5.3 処置・反応判定の簡略化（treatmentEngine / reactionEngine / purityEngine）

| エンジン | 旧役割 | 新役割 |
|----------|--------|--------|
| treatmentEngine | パラメータ選択・段階解放・実行 | レシピ手順の順序検証のみ。正しい手順IDが来たら次の手順へ |
| reactionEngine | 反応計算・最適化判定・除去率/侵食率 | 成功判定を単純化: **正しい手順＝成功**。品質段階（完全/良好/不完全）は手順正確さのみで決める |
| purityEngine | 純度計算・品質スコア | 品質の段階表示（完全/良好/不完全）程度に用途を縮小。数値スコアは内部計算のみ |

**Ep.1 の推奨処置（リン酸／濃度 Lv.3〜4／温度 35〜45℃）は、数値パラメータではなく「レシピの記載内容」として残す。**

---

### 5.4 因果・分岐判定（fateEngine）— 分岐の主役を会話選択へ

- **結末分岐3種**: 完全修復／良好／不完全（判断ポイント1）
- 分岐条件: **観察パートでの情報収集（分析タグ）** と **手順実行の正確さ** で決める。処置パラメータ（酸種・濃度・温度）では決めない
- 金属侵食・ガス事故は結末分岐から外し、「レシピの注意書きを無視したときの反応差分」としてだけ残す

---

### 5.5 会話設計（分析タグの実装）— 観察パートとして実装

EP01 仕様書にある分岐会話＋分析タグの設計を実装し、対話フェーズを「観察・聞き取り」の場にする。

- プレイヤーの選択（何を観察するか、何を聞くか）で分析タグが付く
- タグの組み合わせから「分かりかけていること」がノート形式で提示される（答えではなく、観察事実の整理）
- 化学者の台詞は結論の narrate をやめ、問いかけと観察の促しに寄せる
  - 例（現行）: 「表面の腐食は二層になっている。上層に黒い酸化物——Fe₃O₄……」\n
  - 例（変更後）: 「よく見てくれ。錆の色が、場所で違わないか？」→ プレイヤーが着目点を選ぶ → タグ獲得

## 6. カリキュラム表（Dr.STONE 式ロードマップ）

既存のエピソード計画を、**「依頼を解くたびに次の段階の道具・知識・素材が開く」**ロードマップとして読み替える。

| 段階 | EP | 依頼 | 開くもの（道具・知識・素材） | 解ける問題の範囲が広がる内容 |
|------|----|------|-------------------------------|------------------------------|
| 第1段 | EP01 | 古剣の腐食（ガルド） | リン酸・塩酸、蒸留水、加熱器具、濾過紙、錆の見分け方 | 金属の錆を酸で落とす基礎 |
| 第2段 | EP02 | 染料職人の失敗（ナーラ） | pH試験紙、媒染剤、植物色素、温度計、液の相性表 | 有機物の色を液の性質で定着させる |
| 第3段 | EP03 | 地下水の汚染 | 水質検査キット、蒸留装置、イオン交換樹脂、沈殿反応 | 目に見えない粒（イオン）を分離・検出する |
| 第4段 | EP04 | 貴族のパーティー | 希釈器具、弱酸・弱塩基、指示薬、緩衝液の概念 | 弱い酸でも加減を誤れば傷む、希釈の概念 |
| 第5段 | EP05 | 熱病の集落 | 触媒、純度計算式、合成経路図、副産物分離 | 混ざりものが少ないほど薬は正直に効く（純度・合成） |
| 第6段〜 | EP06〜 | 薬をめぐる倫理 | 用量概念、毒性試験、倫理的判断のフレーム | 薬も毒も、量で決まる |

**ロードマップ表示（知識ノート内の一区画）**
- 現在の段階: 「第1段 酸と錆の基礎」—— 開いている道具・素材・知識の一覧
- 次の段階予告: 「第2段 染料と液の相性」—— 解けると開く道具・素材・知識の予告（詳細は未開示）

## 7. EP01 リデザイン仕様（要約・改訂版）

現行 EP01 への変更点のみを挙げる。

1. **観察パート化**: 線形会話を、EP01 仕様書の分析タグ分岐に置き換える。タグ3種（黒錆／塩化物錆／出自）を集めると観察完了
2. **レシピ提示**: 観察完了後、レシピカード「黒錆の除去」を提示（材料・手順・なぜ1行・注意書き）
3. **手順実行**: 手順を順に実行するだけ。数値パラメータ選択 UI は出さない
4. **品質判定**: 手順正確さで 完全修復／良好／不完全 の3分岐
5. **納品・反応**: ResultScene → DialogueScene で依頼人の反応・会話続き
6. **ノート自動記録**: 実行完了時に該当ノート（上記 §5.1 表）を自動追記、ロードマップ第1段完了表示
7. **学習ループ・予測・パラメータ解放・練習処置・learning.ts は削除**（判断ポイント2）

## 10. 判断ポイント記録（2026-11-26 承認済み）

1. **Ep.1 の分岐結果5種 → 3種に絞る**（完全修復／良好／不完全）。条件は観察タグと手順正確さ。金属侵食・ガス事故は結末分岐から外し、注意書き無視時の反応差分のみ残す。
2. **learning.ts は削除する**。旧ループが UI・テストに滲むのを防ぐため。履歴から復元可能。
3. **ロードマップ画面は独立させず、知識ノート内の一区画（タブ相当）として実装する**。画面遷移を増やさず、既存のノートの器と HUD 導線をそのまま使う。
